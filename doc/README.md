## SAFe Document Convention

The files use a lightweight SAFe structure:

- Epic or Feature Summary
- Business Outcome
- Scope
- Current Architecture
- Key APIs and Data Contracts
- Dependencies
- Nonfunctional Requirements
- Acceptance Criteria
- Risks and Open Questions
- Development Guidance

The repository is primarily educational. Treat the docs as implementation
orientation, not as production governance.
